# Удаление меню на выбранные дни — дизайн

Дата: 2026-07-23. Статус: одобрено пользователем (чат).

## Зачем

Спланированное меню невозможно убрать из бота. Первые семьи будут пробовать
планирование «на посмотреть», и накопленному мусору в календаре некуда деться.
Перезапись дат через новый `/plan` — не замена: она умеет заменить меню другим
меню, но не умеет просто убрать.

## UX-флоу

1. В `/menu` — inline-кнопка «Удалить дни» под текстом меню. Видна только
   администратору семьи. При пустом меню кнопки нет.
2. Тап → экран выбора (`MenuDelete.picking`): по кнопке на каждый день текущего
   меню, «Выбрать все», «Готово», «Отмена». Выбор хранится в state data, тогл
   перерисовывает клавиатуру.
3. «Готово» без отмеченных дней → alert «Отметьте хотя бы один день» (паттерн
   `on_slot` онбординга), состояние сохраняется.
4. «Готово» с выбором → `MenuDelete.confirm`: сколько дней, перечисление дат
   и строка «Список покупок не изменится».
5. «Да» → удаление → сообщение перерисовывается актуальным меню; если меню
   опустело — текст пустого состояния `_empty_menu_text()`.
6. «Отмена» на выборе и «Нет» на подтверждении → возврат к меню без изменений,
   состояние очищается.

## Права

Роутер `menu.py` целиком админом не гейтится: рецепты нужны всем участникам.
Поэтому `IsAdmin()` вешается на конкретные хендлеры удаления, а сама кнопка
скрывается от не-админа при рендере `/menu`. Плюс denied-хендлер на устаревшую
кнопку — тап по старому сообщению не-админом дает alert с именами админов.

Паттерн взят целиком из `profile.py`: кнопка «Редактировать» показывается по
`is_admin(family_member)`, а `on_edit_denied` страхует устаревшие сообщения.

## Механика удаления

- Переиспользуем `repositories.delete_future_meals_on_dates(session, *,
  family_id, dates, from_date)` — функция уже существует и применяется при
  перезаписи дат в `/plan`. Рецепты удаляемых блюд уходят каскадом через
  `Meal.recipe` (delete-orphan).
- `from_date` передается всегда: защита от удаления прошлого, даже если из
  callback_data придет устаревшая дата.
- Даты в callback_data — в ISO-формате.
- Удаление идемпотентно: меню могло измениться между показом пикера и
  подтверждением, несовпавшие даты просто игнорируются.

Новых таблиц и миграций нет.

## Клавиатура

Отдельная `kb_menu_delete_days(days, selected)` в `bot/keyboards.py`, а не
расширение `kb_multiselect`. У пикера дней другие потребности («Выбрать все»,
«Отмена», две кнопки в ряд), а `kb_multiselect` обслуживает онбординг, который
планируется перерабатывать отдельным проектом — связывать два изменения в одном
файле не нужно.

Лейблы дней — через существующий `ru_format.format_date_short`, как в
`_format_future_meals`.

## Состояния

Новая группа в `bot/fsm.py`:

```
class MenuDelete(StatesGroup):
    picking = State()
    confirm = State()
```

Отдельное `confirm`-состояние — по образцу `PlanFlow.approve_confirm`: колбэки
«Да»/«Нет» скоупятся состоянием и не ловятся вне флоу.

## Границы

- **Пустые строки `menus` остаются намеренно.** Удаление всех блюд меню
  оставляет строку в `menus` без блюд. Не чистим: у `shopping_lists.menu_id`
  внешний ключ без `ON DELETE`, и удаление такого меню упало бы по FK, если по
  нему уже собран список покупок. Пустые меню безвредны — `get_future_meals`
  ходит через блюда и их не видит. Альтернатива (миграция с каскадом) не
  оправдана: риск снести список покупок, которым человек пользуется.
- **Список покупок не трогаем.** Привязки пункта к конкретному дню не
  существует: `build_from_menu` схлопывает ингредиенты всего меню в общие
  пункты. Корректно почистить его нельзя — поэтому честно предупреждаем
  в подтверждении, а не делаем вид, что почистили.
- Удаление отдельных блюд внутри дня не делаем: гранулярность только дневная,
  для замены конкретного блюда уже есть флоу в `/plan`.
- Событий аналитики не пишем — спека событий отложена.

## Замеченная неконсистентность (вне этой задачи)

`menu.py` считает «сегодня» как `date.today()`, а `plan.py` — как
`menu_planner.family_today(family)` с таймзоной семьи. Удаление обязано
использовать тот же «сегодня», что и показанный список, иначе пикер предложит
день, которого в `/menu` нет. Поэтому здесь берется источник из `menu.py`.

Само расхождение — отдельный баг: у семьи в дальней таймзоне `/menu` и `/plan`
могут расходиться на день. Чинить его в этой задаче не будем, чтобы не тащить
изменение поведения показа меню в задачу про удаление.

## Тесты

- Unit: кнопка «Удалить дни» есть у админа, отсутствует у обычного участника,
  отсутствует при пустом меню; тогл дня перерисовывает клавиатуру; «Выбрать
  все» отмечает все дни; «Готово» без выбора дает alert и сохраняет состояние;
  текст подтверждения содержит даты и строку про список покупок; «Нет»
  и «Отмена» ничего не удаляют; устаревшая кнопка у не-админа дает alert
  с именами админов.
- Integration: удаление двух дней из четырех оставляет два; рецепты удаленных
  блюд уходят каскадом; «Выбрать все» очищает меню и показывает пустое
  состояние; `shopping_items` после удаления не затронуты; повторное
  подтверждение уже удаленных дат не падает; дата раньше `from_date`
  игнорируется.

## Оценка

XS. Миграций нет, слой данных готов, работа почти целиком в `bot/`.
